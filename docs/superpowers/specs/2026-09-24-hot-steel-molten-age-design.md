# Hot Steel 2.0「熔炉纪元」设计规格

- **日期**: 2026-09-24
- **平台**: Minecraft 1.21.1 / Java 21 / Fabric（沿用现有工具链：Loom 1.17.14、Fabric API 0.116.13+1.21.1）
- **mod id**: `hotsteel` · **包名**: `com.hotsteel`
- **目标**: 在保留 1.4.0 全部内容与数值的前提下，重构架构、新增一条完整剧情主线与一整套更高阶内容，并重绘全部贴图。
- **硬性验收**: `./gradlew build` 通过；`./gradlew runDatagen` 后 `src/main/generated` 无未提交差异。

## 1. 总体结构（重构后的包布局）

```
com.hotsteel
├── HotSteel                 # ModInitializer（注册编排）
├── core/                    # 常量、ID、公共工具
│   ├── HotSteelIds          # id() 统一入口
│   └── ModTiers             # 通用 Tier / ArmorMaterial 注册辅助
├── registry/                # 所有注册表（保持集中、单一职责）
│   ├── ModItems / ModBlocks / ModBlockEntities / ModEntities
│   ├── ModEffects / ModPotions / ModMaterials / ModCreativeTab
│   └── ModEntitySpawns      # 生物生成规则
├── content/
│   ├── item/                # 自定义 Item 子类
│   ├── block/               # 自定义 Block / BlockEntity
│   ├── entity/              # 自定义实体（含 BOSS）
│   └── effect/              # 自定义 MobEffect
├── lore/                    # 剧情系统
│   ├── Chronicle            # 章节数据（静态定义，双语）
│   └── ChronicleProgress    # 玩家进度（data component / attachment）
├── logic/                   # 通用玩法逻辑与服务端事件
├── client/                  # 客户端初始化 / 渲染器 / 模型 / GUI
│   ├── render/              # 实体渲染器与实体模型
│   ├── screen/              # 引导书 GUI
│   └── model/               # 自定义实体模型（ModelPart 层级）
├── data/                    # datagen 提供器（原 datagen 包重命名）
└── mixin/                   # 注入点
```

> 重构原则：**只搬不改行为**。原 `item/ block/ entity/ effect/ logic/ client/ datagen/` 的类迁入上表新位置，逻辑逐字保留；仅在迁移中抽取重复代码（如“点燃目标”“取玩家”等工具方法）。迁移后 `hotsteel.mixins.json`、`fabric.mod.json` 的入口点同步更新。

## 2. 剧情主线「熔炉纪元」（5 章）

剧情通过三件套承载：**引导书 GUI**、**残页解锁**、**成就树**。

| 章 | 标题 | 解锁条件 | 内容要点 | 解锁奖励（残页→章节） |
|---|---|---|---|---|

| II | 熔火之路 | 获得热钢锭 | 岩浆淬炼、超级抗火 | `scorched_page_2` |
| III | 烈火之魂 | 获得熔核 | 烈火怨灵的哀鸣 | `scorched_page_3` |
| IV | 熔铸之躯 | 获得熔铸锭 | 熔核与热钢的融合 | `scorched_page_4` |
| V | 熔炉之主 | 获得熔炉之心 | 击败远古熔铸者 | `scorched_page_5` |

- **引导书**：物品 `hot_steel_codex`，右键打开自定义 `Screen`；左侧章节列表，右侧正文（滚动）；未解锁章节显示为「？？？」。

## 8. 效果矩阵（热钢 vs 熔铸，逐件不重复）

设计原则：**同一槽位两套装备必须给玩家不同的操作决策**，而不只是数值更高。热钢偏「实用/高效」，熔铸偏「炽热支配」，且熔铸在保留热钢核心能力的基础上叠加一个**独有机制**。

| 槽位 | 热钢（实用线） | 熔铸（炽热线，独有机制加粗） |
|---|---|---|
| 剑 | 右键·**火焰突刺**：向前打出一道火（单点） | 右键·**熔火波**：12 格走廊内所有敌人被灼烧并点燃；**对远古熔铸者无效** |
| 刀 | **迅捷之刃**：命中后获得 3 秒迅捷 II | —（熔铸无刀） |
| 战锤 | **碎地重锤**：命中波及并击退周围 2.5 格敌人 | — |
| 三叉戟 | 灼热之刃：命中点燃 | — |
| 镰刀 | **一键收割 5×5** 成熟作物并补种 | —（熔铸用**战镰**：命中横扫 3×3 并点燃，**击杀回血**） |
| 锄 | **范围耕地**：右键土地一次耕出 3×3（不再负责收割） | 3×3 耕地 + **催熟**：周围 5×5 作物各推进一级生长 |
| 镐 | 自动熔炼 | 自动熔炼 + **熔渣回收**：挖矿 15% 额外掉熔核碎片 |
| 斧 | 整树砍伐 | 整树砍伐 + **焦化**：伐倒原木 35% 直接掉木炭 |
| 铲 | 潜行+使用·3×3 挖掘 | 3×3 挖掘 + **玻化**：沙子直接掉玻璃 |
| 镐斧铲 | 三合一 + 自动熔炼 | — |
| 盔甲 2 件 | 火焰结界（免疫火焰伤害，岩浆仍伤） | **熔核护膜**：任何近战打你的人都会被点燃 |
| 盔甲 4 件 | 超级抗火 + 岩浆行走 | 超级抗火 + **熔铸之躯**：岩浆中持续回血、光环扩至 5 格 |
| 胸甲 | 火焰荆棘（被火焰伤害时点燃攻击者） | 见上（熔铸为 2 件触发的通用反燃） |
| 盾 | 格挡免火 + 点燃攻击者 | — |
| 弓/弩/钓鱼竿 | 命中点燃 / 自动烤鱼 | — |
| 熔核 / 熔岩瓶 / 火球 / 苹果 | 一键熔炼 / 岩浆洪流 / 爆炸点燃 / 随身药水 | 熔炉之心（60s 熔炉祝福） |

**修正的三个既有问题**：
1. **锄与镰刀功能重复**：原锄是「3×3 收割」、镰刀是「5×5 收割」，同一件事做两遍 → 锄改为**范围耕地**，收割专属镰刀。
2. **刀完全没有效果**：原实现只是一个`SwordItem` → 补上「迅捷之刃」。
3. **战锤只有面板伤害**：原实现只是一个高攻`MaceItem` → 补上「碎地重锤」。
4. **点燃白名单漏了熔铸武器**：`LivingEntityMixin` 的 `HOT_MELEE` 原先只含热钢近战，导致熔铸剑/战镰/斧命中不点燃 → 已并入。

## 9. 贴图正确性（重要教训）

`lava_golem` / `fire_wraith` / `hot_steel_trident` / `hot_steel_arrow` **复用原版模型**（`IronGolemModel` / `BlazeModel` / `TridentModel` / `ArrowModel`），这些模型在图集里按**硬编码 UV 矩形**采样。因此它们的贴图**不能凭感觉画**，必须：

- 以原版图集为底图重上色，并**保留原版 alpha 轮廓**（`tools/vanilla_refs/` 下的原版 PNG，由官方客户端 jar 提取）；
- 若底图缺失，则退化为**满覆盖**程序化图集（不会出现透明空洞）。

校验方式：比对模组贴图与原版底图的**不透明像素遮罩**必须逐像素相同（`missing=0`）。修复后 4 张贴图全部通过该校验。

> 自有模型的三个新实体（`slag_crawler` / `ember_wisp` / `ancient_forgeborn`）不受此约束，因为模型与图集是同一批设计的。
